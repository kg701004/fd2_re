## 2. 為什麼移除（決策紀錄）

使用者指示，逐步升級，最終明確要求移除整個原始碼樹：

1. 「已經命令你不准使用remake了」——禁止執行 remake
2. 「Phase 4整個先暫停」——暫停 M5 Phase 4
3. 「那就把這項移除 **我不需要remake驗證過的資料 那本身就有問題 驗出來的也會有問題**」
4. 「remake驗到的問題都先移除 把remake驗過的都改用原版驗證」
5. 「把remake版本程式移除」→ 經確認範圍後刪除整個 `remake/`

**核心理由**：使用者判定「以 remake 執行結果作為驗證來源」這件事本身不可信，
因此由它產出的結論也不可信。**被否定的是驗證方法，不是 RE 知識本身**。

**同一天的稽核結果支持了這個判斷**（見 §4）：`docs/figures/` 裡 18 張
「原版 vs 重製」對照圖中有 **13 張是自我複製**，兩側逐位元組相同，根本不構成對照。

**影響**：M5 的驗收句（「正常玩法可達、無 debug hook」）目前**沒有任何達成路徑**，
因為要驗收的對象已不存在。要重啟需要使用者重新決定方向，不是文件能單方面決定的。

**復原方式**：程式碼完整保留在 git 歷史，`git log --all -- remake/`。

## 4. 證據可信度稽核（本次最重要的發現之一）

對 `docs/figures/` 全部 212 張圖做「同一份 RGB bytes 掛不同檔名」檢測：

- **18 張 `*original-vs-remake*` 中，13 張兩半逐位元組相同** → 是自我複製，
  從未真的跑過原版對照。只有 5 張是真的（全部是 2026-08-25/26 改用
  `dosbox_diff_harness` 之後才產出的）。
- `shop-sell-slot-cleared-original-dosbox.png` 與
  `shop-transfer-result-verified-original-dosbox.png` **逐位元組相同**，卻被引用為
  兩個不同結論的證據；圖中商品仍在列表裡，根本不呈現「欄位清空」。
- 另有教會兩張圖掛兩個檔名、轉職 trial3／trial4 差異圖完全相同。
  **後者已於 2026-09-03 查明，不是檔案覆寫**：本文件自己的數值表記載 trial3／trial4 六個
  成長欄位完全相同，而該畫面經 5 張圖兩兩差分證實是**完全確定性**的（所有差異都只落在同一個
  28×68px 數字欄位內，沒有動畫／游標／時序雜訊），故數值相同必然逐位元組相同。
  **但連帶修正了一個被高估的說法**：那 5 次 trial 不是 5 個獨立樣本（RNG 綁按鍵/tick 數而非
  時間），所以原記的「range PASS(5/5)」不應被引用為「已用 5 個獨立樣本驗證」。詳見 doc58。

**結論**：這批被證偽的圖，其原始命題是「remake 與原版一致」。`remake/` 既已移除，
**這類 parity 命題本身已失去意義**；有價值的只剩「原版本身長什麼樣」，該部分已用
純原版重新補拍（§5）。完整清單與各自半邊 MD5 見 doc58 2026-09-03 段落。

## 8. 已知限制與風險

1. ~~**`dosbox_harness.sh` 的 `pick_display_port()` 不是 concurrency-safe**~~
   → **已修復（2026-09-03）**。改為 `reserve_display_port()`：在 flock 保護下
   「選擇 + 寫出 reservation」是同一個原子動作，選擇釋放鎖前就對其他 launcher 可見。
   回歸測試 `tools/test_dosbox_harness_ports.sh`（21 項全過，含一項**證明測試本身有效**的
   control：5 條並行裸掃描必定全部相撞＝修好前的行為）；整合實測三個並行 launch 落在
   :199/:299/:399，三張截圖內容互異。`fd2_original_verify.py` 的 workaround 鎖已解除
   （預設平行，`--serial-launch` 為退路）。詳見 doc98 同日段落。
   **殘留邊界**：只保證本 harness 自己的分配；完全不透過本 harness 的外部程序同瞬間搶
   同一 port 仍可能相撞（實務上不存在，但不宣稱已解決）。
2. **frame MD5 不能單獨當畫面 identity**：含待機動畫 sprite 的畫面本來就會變
   （實測 0.54~0.57% 像素、單一 48×48 框）。
3. **`launch` 必須保持存活**：用 `subprocess.run(timeout=...)` 呼叫會殺掉 launcher
   並連帶收掉 instance（症狀是全黑畫面）。
4. **章節 patch 只改章節 byte，名冊維持原存檔狀態**：用 ch26 存檔跳到 ch02 時，
   角色數值是 ch26 的，不是 ch02 真實值。要真實值必須開新遊戲。
5. §4 那 13 張被證偽圖背後的原始結論，目前**沒有對照證據**，需要時得逐項重測。
6. 整備（選人）畫面尚無原版基準：只有 ch23-25/28-31 會顯示，且會撞既有記載的
   人數門檻（本機存檔 13 人不足）。評估為**成本高、價值低**，未做。
