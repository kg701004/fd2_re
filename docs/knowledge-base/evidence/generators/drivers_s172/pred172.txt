續一百七十二 實機 lc172a 之前寫的預測(2026-10-30;寫完才跑實機,事後不改)。

設定:原版 FD2.EXE、開機 → 標題 → START → 16 秒;FD2_HARNESS_DOS_TIME=12:00:54(FD2.EXE 之前 TIME);
SEGS 3000-3800,3800-3810:x,3810-6300,6300-6310:x,6310-24000;FD2_CALLLOG_SLICES=1。

P1 DH = 0 那一秒(續一百七十一 NOT TESTED):delay 迴圈(0x3e04f 之後)的 int 21h,DOS 秒數不是 0 時 CF = 1 走短路;
   DOS 秒數 = 0 的那一段(BIOS tick 18 或 19 個,約 0.99 .. 1.04 秒)每一次都走長路。G 窗 3000 .. 24000 ms 裡
   只有一段這樣的連續長路,出現在 TIME 之後約 6 秒(模擬時間;TIME 執行的模擬時刻沒記錄,所以只預測「恰好一段、長約 1 秒」)。
   反例 0 才算成立。

P2 時間片:每個時間片結束時核心迴圈 `while (CPU_Cycles-->0)` 多減一次,所以每片多 1 個週期:
   (a) 每次乾淨的 delay(2):Δb == Δk(每片恰好 1);
   (b) 續一百六十五的殘差(5000·Δt − Δn)跳的那一階約 45.5 個週期 = Δk 的差;每 ms 約 22 個時間片的來源要另外找;
   (c) Δw 每次 int 21h 固定 = 4 個 rep 的次數和 14 + 31 + 12 + 31 = 88(delay(2) 18 次 = 1584),不隨時段變。

P3 rep 多記:4 個 rep 位置(0080:06b0、0088:0e1f、0070:0cd4、0088:21b5)在 S 紀錄裡連續出現的次數 = ⌈N / 4⌉(N = 14 / 31 / 12 / 31)
   或多 1;多 1 的每一次,重複的那幾筆之間 k 都有增加(時間片在 rep 中間結束)。

P4 137c(DIG 驅動的 int 66h 分派段):3400 .. 3700 ms(續一百七十一的空窗)裡第一次執行 137c,而且第一次是 DIG 自己的功能
   (AX 在 0x300 .. 0x4ff,走 0x17b 以後),之後 MDI 呼叫(0x502)才經過它(0x172 → 0x1ea → 0x1fa ljmp cs:[0x36])。

P5 鍵盤 IRQ(int 09h)在遊戲碼收時,處理到回到被中斷位置是 532 .. 533 條非遊戲指令(lc171a 四次);START 那一下 Return
   若撞上重入,重入之後的非遊戲指令 = 69 / 70 + 532 .. 533(續一百六十五 lc163a 的 601、lc171a 的 601)。撞不撞得上不預測。
