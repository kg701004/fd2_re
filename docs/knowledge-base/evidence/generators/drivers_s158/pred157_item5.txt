續一百五十七第 5 項(重跑,使用者 2026-10-27「未確認的部分依建議逐項自動處理」)——量之前寫下的預測。
做法:序章戰場、敵 #11..#16 各只會一個法術(1、2、5、7、3、6)搬到索爾旁、[0x53af9] = 0(同第 4 項)、索爾 HP = 1;
結束回合讓索爾倒下 → GAME OVER → 標題;之後照 lc131a 的清對話迴圈(Return、等 0.6 秒、截圖、cursor_tile_is_empty,最多 20 次)送鍵,
主機端記每次送鍵 / 截圖的起訖時間;呼叫紀錄(ICOUNT,閘門 = show_result_resource_79 0x22e5c)記標題序列與讀鍵的模擬時間。

靜態依據(FD2.EXE 反組譯):delay(ms) 0x3e01d 的圈數 = (ms × [0x541b0] + 500) / 1000,每圈一次 int 21h AH=2Ch,
[0x541b0] = 開機時量的「一秒內 int 21h 次數」;選單確認後 0x1fef0 閃爍 4 ×(delay 0x50 + delay 0x50),0x1ff31 淡出(0x1f882),0x1ff36 清畫面。

P1 [0x541b0] ≠ 0;閃爍(E 0x1fef0 → E 0x1ff31)模擬時間 = 640 ms ± 15%;淡出(E 0x1ff31 → E 0x1ff36)≤ 300 ms;合計 ≤ 0.9 s。
P2 0x1fd7c(選單前 kbd_flush)之後到 0x1fed3(確認)之間,選單只讀一個鍵(0x1fe63 一筆),就是確認那個 Return。
P3 以 has_key(0x10620)/ 讀鍵的事件對齊主機與模擬時間後,確認的讀鍵落在恰好一次送鍵之後 0.3 s 內,且那次送鍵是 0x1fd7c 之後的第一次送鍵。
P4 截圖規則(續一百三十八用在 lc131a 的):「最後一張靜止選單之後的下一張」的編號 = P3 得到的確認送鍵編號。
P5 迴圈期間模擬時間與主機時間的比 0.9 .. 1.1。
