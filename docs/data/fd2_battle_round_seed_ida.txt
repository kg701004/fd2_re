FD2 戰鬥初始回合寫入端（IDA Pro 9.4＋Capstone 5.0.3）
=========================================================

輸入與位址空間
--------------

- 檔案：`FD2.EXE`
- 大小：357074 bytes
- MD5：`b97caf2239a27a896069d03549d96e1e`
- SHA-256：`222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- `0x...` 是 IDA database／LE object 的線性位址（EA），不是未標示的
  檔案偏移。
- 第一順位：使用者授權的 IDA Pro 9.4 無網路 Docker；第二順位：
  `fd2-cap-local`／Capstone 5.0.3。

直接指令
--------

IDA 將目標固定在 `sub_205DA`，範圍 `0x205DA..0x2067D`。29個直接呼叫者
分布於章節開場處理器 `0x3231B..0x33E3C`；函式先載入目前原始章節編號，
清除32-byte戰鬥區域狀態與相關全域值，建立第一張地圖畫面並淡入，最後
才設定回合：

```text
0x205F9  push dword [0x53C03]
0x205FF  call 0x1088D
0x2060B  push dword [0x53AD5]
0x20611  call memset
0x20655  push 1
0x20657  call 0x11CAC
0x2065F  mov dword [0x51A83],1
0x20669  call 0x1F525
0x2066E  mov dword [0x53BEF],1
0x20678  jmp 0x17EE8
```

Capstone 對 `0x205DA..0x2067D` 的獨立重生得到相同指令，並將
`[0x3BEF]` fixup 標為 `0x53BEF`。

結論與界線
----------

- **已證實**：原版章節戰鬥初始化完成時，原生回合計數器
  `[0x53BEF]` 是1。
- **已證實**：`0x1A5B9` 是後續遞增端；CONTINUE 則以目前快照標頭 `+0`
  保存並恢復即時計數器，不能重設成1。
- 重製端從固定原版地圖新建 `battle.State` 時可安裝初始值1；手工建立、缺少
  固定雜湊出處的 `State` 仍保留0並失敗即關閉。
- 這只閉合計數器寫入端，不自行證明每個陣營階段的完整高階名稱與介面畫面。
