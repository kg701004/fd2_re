已證實的顯示消費端
------------------

IDA Pro 9.4 在 `0x30A47..0x30C22` 的狀態／復活介面中顯示：

    0x30B07  movzx eax, byte ptr [esi+20h]
    0x30B0B  add   eax, 96h
    0x30B10  push  eax
    0x30B17  call  sub_15F84

另一個狀態介面 `0x31019..0x311DC` 同樣在 `0x310B5` 讀取 record
`+0x20`，於 `0x310B9` 加 `0x96`，再呼叫 `sub_15F84`。兩個消費端都
沒有把 class 限制為 0–26；顯示索引是 `150 + raw class`。

固定雜湊 `FDTXT_000.bin` 的直接解碼結果為：

- 索引 176（class 26）：glyph `[180,180,180]`，文字「？？？」
- 索引 177（class 27）：glyph `[181,181]`，文字為兩個全形空格「　　」
- 索引 178（class 28）：glyph `[180,180,180]`，文字「？？？」

已證實的裝備表消費端
--------------------

`0x1C1C3..0x1C220` 讀取 runtime record `+0x20` 後呼叫 `0x4E53E`；
`0x4E53E..0x4E555` 以 class 乘 7，再加表基址 `0x6188A`。該直接索引同樣
沒有 0–26 上限，表內 27／28 列必須保留。

結論與限制
----------

- class 的已證實資料域至少是 0–28。
- class 27 的原版顯示文字就是兩個全形空格；不得自行發明語意名稱。
- class 28 的原版顯示文字就是「？？？」；這是逐字還原，不代表已推定其
  遊戲設計語意。
- `cls28`、`?`、「職業28」及「class 27／28 因來源衝突而拒絕」都是舊
  重製端占位或錯誤斷言，不能再作為正式規則。
- 本證據只閉合文字索引與裝備表資料域，不證明原生 LOAD／CONTINUE、
  portrait、sprite、章節節點或其他 persistent party 欄位已完成。
