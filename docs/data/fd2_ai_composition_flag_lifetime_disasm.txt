# IDA Pro 9.4（2026-07-29）確認：
# * 0x1D8BA..0x1DA16 是敵方兩段掃描；0x1D988 是同一函式內第二段，
#   不是獨立函式。
# * 0x1598A..0x15B77、0x1567E..0x15880 是兩個預選 producer。
# * 0x1CFF0..0x1D4CB 是玩家命令 selector；0x1BBDC..0x1BFFE 是物品路徑。
# * 上述 producer／selector 都直接呼叫 0x4DBFC 恢復構成格基底；
#   它們沒有呼叫 0x145CD。
#
# 結論邊界：
# * `0x4E031` 只複製 BIOS 鍵盤緩衝 word，與構成格旗標無關。
# * `0x1598A` 每次 0x4E040 目的格搜尋後呼叫 0x4DBFC，再於每次
#   0x14818 目標搜尋後再次呼叫 0x4DBFC。
# * `0x1567E` 也在目的格／目標搜尋後各自呼叫 0x4DBFC。
# * `0x1CFF0` 在玩家每一階段 0x14818／0x115B6 後呼叫 0x4DBFC。
# * 因此這些命令的 baseline 是每次由 FDFIELD `+2 & 0x1F` 重建的短生命週期
#   緩衝區；不可在重製 `State` 保存一份跨命令的 live flags。
# * `0x145CD` 的 0x40／0x80 writer 只屬其直接呼叫者的移動／攻擊生命週期。
