```text

0x13b49  jnz 0x13b66

0x13b4c  push esi

```

`0x13b1e→0x13c06` 不是只代表「共用收尾」；`0x13c06` 會先測試
`0x14237` 的回傳值，為 0 時由 `0x13c0f` 呼叫 `0x13fd4`，之後才進
`0x13e57`／共用收尾。`sub_14237` 的 IDA 輸出在 `0x145c3` 以
`xor eax,eax` 結束；無 equipped low item 時也直接跳到同一尾端。因此
在目前已證實的函式控制流中，mode 2 的失敗路徑確實會進入
`0x13fd4`，不是只由 direct-xref 清單判斷。

```text
0x14EF0 成功 → 0x13e5a 共用收尾
0x14EF0 失敗 → 0x14237
  → 0x14237 回傳 0 → 0x13c06 → 0x13c0f → 0x13fd4 → 0x13e57
```

因此 mode 2 的已證實控制流是：

```text
0x14EF0 成功 → 共用收尾
0x14EF0 失敗 → 0x14237 → 0x13FD4 → 共用收尾
```

此分支沒有 `call 0x13e9c`；原先「沒有 `0x13fd4`」的敘述已撤回。
`0x13b5f` 不在 `sub_13FD4` 的 direct-xref 清單，只代表呼叫經由
`0x13c0f` 的共用基本區塊，不能推論為執行期不會抵達。`PlanNativeUnitMode2`
現在保存 `[0x14ef0, 0x14237, 0x13fd4]`。
