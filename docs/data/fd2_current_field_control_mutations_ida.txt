FD2 current snapshot 的 FDFIELD 控制映像生命週期（IDA Pro 9.4）
================================================================

證據範圍
--------

- `FD2.EXE` 大小：357074 bytes
- MD5：`b97caf2239a27a896069d03549d96e1e`
- SHA-256：`222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- 下列 `0x...` 是 IDA database 線性位址（EA），不是未標示的檔案偏移。
- 第一順位：使用者合法 IDA Pro 9.4，只在授權、無網路 Docker 流程執行。
- 第二順位：`fd2-cap-local` 的 Capstone 5.0.3，覆核下列直接寫入。

結論
----

`[0x53A55]` 不是載入後永遠等於 FDFIELD resource `3N+1` 的靜態
buffer。原版在戰鬥中會直接改寫其中的回合事件與寶箱控制值；current-save
writer 因而必須保存完整 live `0x8A3` 映像。CONTINUE bridge 不可用
`map.json`、重新解包的原始控制資源或由欄位重建的近似資料覆寫存檔映像。

使用者 2026-07-30 checksum-valid chapter0 snapshot 的有效前綴剛好與
FDFIELD resource 1 全同，只能證明該次擷取尚未在這些 bytes 形成差異；
不能外推為所有章節、回合與事件都永遠相同。

直接 writer
-------------

### 寶箱控制值

`0x190AC..0x1956B` 以三位元組索引讀取
`[0x53A55]+0x53+slot*3`。交易成功後：

```text
0x19344  mov edx,[0x53A55]
0x1934A  mov eax,slot
0x1934C  shl eax,2
0x1934F  sub eax,slot
0x19351  add eax,edx
0x19357  mov word [eax+0x54],dx
```

也就是 live chest `value` 會被直接改寫，不是唯讀資源欄位。

### 回合事件 turn byte

IDA 對 `[0x53A55]` 的完整 data xrefs 找到多個章節 handler 直接 writer。
例如 `0x34A7A..0x34B5D`：

```text
0x34AA7  mov dl,[0x53BEF]
0x34AAD  inc dl
0x34AAF  mov eax,[0x53A55]
0x34AB4  mov [eax+3],dl
0x34AB7  mov dl,[0x53BEF]
0x34ABD  add dl,2
0x34AC0  mov eax,[0x53A55]
0x34AC5  mov [eax+6],dl
```

其他直接 writer 包含：

- `0x358BA`：寫 turn event 0 的 `+3`；
- `0x359BB`：寫 turn event 0 的 `+3`；
- `0x35A44`：寫 turn event 1 的 `+6`；
- `0x35AF8`：寫 turn event 2 的 `+9`；
- `0x35C71`：寫 turn event 0 的 `+3`；
- `0x35D45/0x35D5C`：分別寫 turn event 1／0 的 `+6/+3`；
- `0x35D9D/0x35DF1`：寫 turn event 1／2 的 `+6/+9`；
- `0x35F02`：寫 turn event 2 的 `+9`；
- `0x35F8E`：寫 turn event 0 的 `+3`。

這些位址只證明 raw turn byte 的 live 更新；個別章節的高階事件名稱仍應由
各 handler 的控制流程另行閉合。

### event62 產生端與 event63 消費端

**已證實**：map26 原始 control row0 是 `ff 3f 00`，即尚未排入回合的
event63/raw camp0。event62 handler `0x35898..0x358C6` 在 battle-local
state byte17 為零時，以 `0x358BA mov [eax+3],dl` 寫入
`[0x53BEF]+1`，再於 `0x358C2` 將 state byte17 設為1。這閉合了休眠列的
寫入端；`0xff` 不可再因解析器只輸出已啟用回合而被丟棄，也不可解讀為第255回合。

```text
0x358A2  mov eax,[0x53AD5]
0x358A7  cmp byte [eax+0x11],0
0x358AB  jnz 0x358C6
0x358AD  mov dl,[0x53BEF]
0x358B3  inc dl
0x358B5  mov eax,[0x53A55]
0x358BA  mov [eax+3],dl
0x358BD  mov eax,[0x53AD5]
0x358C2  mov byte [eax+0x11],1
```

**已證實**：event63 handler `0x358C7..0x358E5` 先後呼叫 staging helper
`0x35822` 兩次。來源 `PUSH` 順序是 `(group,y,x)`：第一組
`(1,27,3)`，第二組 `(2,27,15)`；helper 內 `0x35834` 呼叫
`0x135DD(x,y)`，`0x35842` 呼叫 `0x10B4E(group)`。因此來源參數不可標成
`0x35822(x,y,group)`，也不可依原陣列索引把 group 與 x 對調。

```text
0x358D1  push 1
0x358D3  push 0x1B
0x358D5  push 3
0x358D7  call 0x35822
0x358DF  push 2
0x358E1  push 0x1B
0x358E3  push 0x0F
0x358E5  jmp 0x35318       ; shared call 0x35822 tail

0x3582C  push dword [esp+8]
0x35830  push dword [esp+8]
0x35834  call 0x135DD      ; x,y
0x3583C  movzx eax,byte [esp+0xC]
0x35841  push eax
0x35842  call 0x10B4E      ; group
```

CONTINUE bridge 邊界
--------------------

- 存檔 `NativeFieldControl[0x8A3]` 是唯一 live 控制映像來源。
- selected chapter 的 FDFIELD/FDSHAP 資產仍負責 composition、terrain 與
  靜態規則；它們不能反向覆寫 live control。
- 現有 runtime `0x50` records 是目前已出場單位的唯一 live 來源。
- control `+0x83` 的 26-byte rows 只供 `0x10B4E→0x10C50` 之後的 group
  append 使用；不可用它重建或重排已保存的 runtime records。
- `0x10C50→0x1B750` 的 future-group constructor transaction 已由後續直接
  證據與具型別 helper 閉合；未改寫 live turn/event 的 chapter0 排程也已有
  嚴格 pending-roster consumer。正式 CONTINUE 仍因 handler-mutated turn
  slots／group formulas 的通用 pending-group binding，與 `0x117E7` 對應的
  `Game` controller handoff 未接而維持失敗即關閉。
