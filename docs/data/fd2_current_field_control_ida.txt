FD2 current snapshot 的 FDFIELD 控制映像（IDA Pro 9.4）
=========================================================

證據範圍
--------

- `FD2.EXE` 大小：357074 bytes
- MD5：`b97caf2239a27a896069d03549d96e1e`
- SHA-256：`222b7d067ad4450eb9c5f6e6bce1797d54bb050417ba39ced6067f8039f28c4f`
- 第一順位：使用者合法 IDA Pro 9.4，只在授權、無網路 Docker 流程執行。
- 第二順位：`fd2-cap-local` 的 Capstone 5.0.3，覆核下列直接複製邊界。

來源與對稱保存
--------------

新章載入器 `0x1088D` 從 `FDFIELD.DAT` 載入資源 `chapter*3+1` 到
`[0x53A55]`。這是每張戰場的控制資源，不是未分類的泛用 battle state：

- `+0` 供 FDSHAP 資源選擇使用；
- `+1` 寫入 `[0x53BE7]`，並參與建立執行期名冊數量；
- `+2` 寫入 `[0x53BE3]`；
- `+3` 起是 `0x1A813` 消費的 16 筆三位元組回合事件；
- `+0x33` 起是 `0x13A44` 消費的 16 筆
  `(event_id, selector)` 格子事件；
- `+0x83` 起是 `0x10B4E` 以 26 bytes stride 掃描的 FDFIELD 單位列。

`0x10BC7..0x10BF6` 也固定了 `+2` 的邊界語意。原版令索引 `ebx=0`，
先以 `cmp ebx,[0x53BE3]; jge done` 判斷，再讀
`[0x53A55]+0x83+ebx*0x1A`；因此 `+2` 是排他的有效筆數，不是最後索引。
有效列嚴格是 `0..count-1`，控制資源或固定容量映像中 count 以後的 bytes
只保留 raw，不得解碼成額外 live unit。

使用者 2026-07-30 checksum-valid current snapshot 的動態旁證也符合此
契約：raw chapter 0 的 header `+2=30`，其前 `937` bytes 與固定雜湊
FDFIELD resource 1（`0x83+31*0x1A`）逐 byte 相同；但原版上述迴圈只
消費前 30 列。第 31 列與固定 `0x8A3` 映像尾端仍保持未分類，不因檔案
長度而提升為有效單位。這份存檔會變動，不列入固定版本基準。

current-save writer `0x19DF7..0x1A30B` 將 `[0x53A55]` 起固定
`0x8A3` bytes 寫到 plaintext `+0x0000`。CONTINUE loader `0x10010`
在 `0x101C3..0x101D7` 對稱地把同一範圍複製回 `[0x53A55]`，隨後呼叫
`0x10652` 依 raw chapter 釋放或準備章節專用 FDOTHER 輔助圖形緩衝區。
因此 `FD2.SAV+0x0000..+0x08A2`
是 FDFIELD 控制段的固定容量執行期映像，不是語意未知的單一戰鬥區塊。
`0x10652` 本身不載入 FDFIELD／FDSHAP／FDTXT；其狹窄行為與舊
`load_ch_bg` 名稱勘誤見
[`fd2_chapter_aux_graphics_10652_ida.txt`](fd2_chapter_aux_graphics_10652_ida.txt)。

重製邊界
--------

`fdsave.CurrentSnapshot.NativeFieldControl` 以 `[0x8A3]byte` 原樣保存此
映像。後續 `ContinueFieldControlView` 已依上述固定 layout 唯讀拆出
raw map selector、own-deploy count、unit count、16 筆三位元組回合事件、
16 筆二位元組格子事件、16 筆三位元組寶箱控制，以及 count-delimited
26-byte 單位列；回歸明確固定 `count=30` 只產生 30 列，不暴露第 31 列
padding。未解欄仍保留 raw bytes，不命名。

這段控制資源不是 `[0x53A51]` 指向的地圖構成格陣。CONTINUE 會另行
從 FDFIELD resource `3N` 載入 composition，並由 `0x4DBFC` 重設 live
cell byte `+3`；不可拿控制映像或 `map.json` 的 serialized byte `+3`
代替。typed control、runtime records／selector cache、timing 與
future-group constructor 已由後續具型別交易閉合；未改寫 live turn/event 的
chapter0 排程也已有嚴格 pending-roster consumer。CONTINUE 正式接入仍需
handler-mutated turn slots／group formulas 的通用 pending-group binding，並把
完整 `battle.State` 原子交給 `0x117E7` 對應的 `Game` controller。唯讀解析
本身不代表 CONTINUE 已可供玩家使用。
