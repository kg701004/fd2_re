已證實：sub_23A0A 控制流程
-------------------------
- 函式範圍：0x23a0a..0x23b5f；dispatch call site：0x25e23。
- 0x23a5e 呼叫 sub_233C6；0x23a95 呼叫 sub_11506。
- 0x23a66..0x23a84 將 0x42..0x49 依序傳給 sub_3453E，計算回傳非零的筆數。
- 0x23a9a 比較 dword_53BEF > 0x12；成立時跳到 0x23abd。
- inactive 計數 > 4 時也在 0x23aa3..0x23aab 跳到 0x23abd。
- 兩者皆不成立時，0x23aad..0x23abb 讀取 `[dword_53A45 + 0x42]`
  的 u16，並與 0x140 比較。
- `< 0x140` 會落入 0x23abd：dialog index 2 → ACTING 49 → dialog index 3；
  0x23b1f 直接跳到 0x23b52，因此不執行 JOIN18。
- `>= 0x140` 會跳到 0x23b21：dialog index 4 → 0x23b4a 的
  sub_112A5(0x12)；接著才到 0x23b52 增加章節。
- 所以 JOIN18 只屬於 `NOT(round > 18 OR inactive_count > 4) AND
  slot0.word42 >= 0x140` 分支，絕非共同尾端。

已證實：sub_3453E 是 0x50-byte runtime record 索引
---------------------------------------------------
- 函式範圍：0x3453e..0x34565。
- 0x34548 讀取參數；0x3454c..0x34553 計算 `index * 0x50`。
- 0x34556 讀 dword_53A45；0x3455b 讀取該 record 的 byte `+5`；
  0x3455f 套用 `& 1` 後回傳。
- 因此 ch15 傳入的 0x42..0x49 是 runtime record slots 66..73，
  不是角色編號或事件索引。對 bit0 的高階名稱仍維持未知。

已證實：sub_233C6 的 layout 寫入
---------------------------------
- 函式範圍：0x233c6..0x234bb。
- 0x233ea..0x23429 逐筆寫 runtime record `+0/+1/+3`。
- 0x2342b..0x23458 可另外寫一個 special slot。
- ch15 call site 的直接參數固定 slots 0..15、special slot 65
  `(28,30,pose2)`，camera 原始 scalar `(22,25)`。

已證實：零起算 handler 與 persistent-first 建構
-------------------------------------------------
- 主迴圈 `0x25e23` 以目前 `[0x53c03]` 選 post-handler；handler 自己才把
  章節加一。因此 raw `ch15_post` 是第16戰戰後，不是第15戰戰後。
- `sub_320FC`（0x320fc..0x321c8）先保存完整 `0xA00` persistent array，再把
  已選的 `0x50` records 排到前面、未選 records 排到後面；`[0x53BFB]` 總數不變。
- `sub_1088D` 在 0x10987..0x1099a 以 FDFIELD header byte1 初始化 runtime count；
  0x10a77..0x10aad 依 persistent array 順序完整複製，名冊不足固定槽數時才在
  0x10b06..0x10b13 寫零 record 並把 byte+5 設為1。
- 複製完 fixed party slots 後，0x10b3e 才呼叫 `sub_10B4E(0)`；後者
  （0x10b4e..0x10c4f）掃描
  全部 FDFIELD rows，group byte+0x15 等於0就無條件呼叫 `sub_10C50` append，
  未見針對 `fig=15` 的 skip／replace gate。
- 第16戰 map15 的 FDFIELD header 固定16個 party slots，group0有60筆，故
  post-handler 入口為 `16+60=76` records。這是雜湊綁定原始資料與直接指令的
  靜態閉合；尚未提升為一般玩家路徑 E2。
