已證實：dispatch owner 與 IDA 函式邊界
------------------------------------
- post-handler table `0x51de9` 的 index12 位於 `0x51e19`；原始 bytes
  `9f 38 01 00` 直接解碼為入口 `0x2389f`。
- 玩家第13戰使用 raw map/chapter index12，所以正確 consumer 是
  `postbattle_ch13_persist`，不是舊同號接法 `postbattle_ch12_persist`。
- IDA 將 `0x2389f` 歸在較大的 `sub_237D5` 範圍 `0x237d5..0x239bd`；
  這個導覽用函式邊界不能覆蓋 table 保存的真實 interior entry。證據與 binding
  均保留原始入口 `0x2389f`，不以自訂函式名取代。

已證實：直接控制流與持續隊伍尾段
----------------------------------
- `0x238c0 push 9`、`0x238c2 push [0x53a79]`、`0x238c8 call 0x15f84`：
  使用目前 FDTXT table 的 raw index9。
- `0x238d0 call 0x11506`：對話完成後同步 persistent roster。
- `0x238d5 push 3`、`0x238d7 jmp 0x237c8`；`0x237c8 call 0x112a5`
  因而執行 JOIN character3。這是實際跳轉，不是匯出器污染。
- `0x237d0 jmp 0x231f2`；`0x231f2 inc [0x53c03]`，`0x231f8 return`。
  handler 的可見順序因此是 dialog→sync_party→JOIN3→chapter13。
- `0x2389f..0x238dc` 沒有條件分支或未知 call target；IDA 與 Capstone 對上述
  指令、參數及跳轉目標一致。

已證實：跨場景文字映射
----------------------
- FDTXT_013 index9 含12句，`count-aligned.json` 依原始 utterance 順序精確對到
  `ch13.json` scene3 lines0..5，接著 scene4 lines0..5；不能扁平成單一 scene。
- `ch12_post.json` authored binding 以 call-site `0x238c8` 綁定
  `FDTXT_013/ch13.json`。現行 compiler 會把多個 target 自動 lower 成依序的

  sync→JOIN3→chapter13；缺 mapping 時仍由 compiler 失敗即關閉。
